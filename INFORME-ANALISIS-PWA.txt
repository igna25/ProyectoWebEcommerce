║  1. RESUMEN EJECUTIVO                                                       ║
╚══════════════════════════════════════════════════════════════════════════════╝

El proyecto IAW-commerce es una aplicación web progresiva de e-commerce
desarrollada con Next.js 14 (App Router). Incluye funcionalidades de catálogo
de productos, carrito de compras (con soporte online y localStorage para
usuarios no autenticados), panel de administración, integración de pagos con
MercadoPago, autenticación con NextAuth, y gestión de imágenes con Cloudinary.

Tras el merge de la rama pwaAdmin, se incorporaron:
  - API routes dedicadas para el panel de administración (/api/admin/*)
  - Componente PersistAdminRole para persistir el rol de admin en localStorage
  - Sistema de cache en localStorage para datos del admin (adminCache.ts)
  - Componentes client-side para el admin: AdminHomePage, ProductsListAdmin,
    SalesListAdmin
  - Cache separado en el Service Worker para APIs de admin (ADMIN_API_CACHE)
  - Manejo diferenciado de GET vs POST en el SW para rutas admin

La aplicación tiene una base PWA funcional y ahora incluye soporte offline
para el panel de administración, pero le faltan piezas clave para ser una
PWA completa. Además, el merge introdujo algunos problemas nuevos que se
detallan en este informe.

║  4. HALLAZGOS — PROBLEMAS DE PWA                                            ║
╚══════════════════════════════════════════════════════════════════════════════╝

─── 4.1 Manifest incompleto ───────────────────────────────────────────────────

  PROBLEMA:  El campo "description" del manifest.webmanifest está vacío ("").
  IMPACTO:   Afecta la puntuación en auditorías Lighthouse y la presentación
             del diálogo de instalación en navegadores que muestran la
             descripción (Chrome, Edge).
  UBICACIÓN: public/manifest.webmanifest, línea 4
  NOTA:      Ya existe una buena descripción en el metadata del layout.tsx
             que podría reutilizarse.

─── 4.2 Íconos insuficientes ──────────────────────────────────────────────────

  PROBLEMA:  Solo existen íconos de 192x192 y 512x512.
  IMPACTO:   Distintos dispositivos y sistemas operativos requieren íconos
             de diferentes tamaños para splash screens, accesos directos del
             sistema, notificaciones, etc.
  UBICACIÓN: public/icons/ (solo 4 archivos)
  RECOMENDACIÓN: Agregar al menos: 48x48, 72x72, 96x96, 128x128, 144x144,
                 256x256, 384x384 (tanto regulares como maskable).

─── 4.3 apple-touch-icon inexistente ──────────────────────────────────────────

  PROBLEMA:  El layout.tsx declara apple: "/icons/apple-touch-icon.png"
             pero ese archivo NO existe en public/icons/.
  IMPACTO:   En dispositivos iOS/Safari, al hacer "Add to Home Screen", el
             ícono se generará automáticamente como un screenshot de la página
             en vez de mostrar el ícono de la app.
  UBICACIÓN: src/app/layout.tsx, línea 18 (referencia rota)
             public/icons/ (archivo faltante)

─── 4.4 Precaching muy limitado ───────────────────────────────────────────────

  PROBLEMA:  En el evento install del SW solo se precachean 3 recursos:
             "/", "/offline" y "/manifest.webmanifest".
  IMPACTO:   Las rutas /dashboard, /login, /cart, /buyProduct, /admin y
             todas sus subrutas NO están precacheadas. Tampoco los bundles
             JS/CSS de Next.js (/_next/static/...).
  UBICACIÓN: public/sw.js, líneas 18-27 (evento install)
  NOTA:      La estrategia network-first cachea páginas visitadas, pero
             solo DESPUÉS de haberlas visitado online.

─── 4.5 Sin soporte de Push Notifications ─────────────────────────────────────

  PROBLEMA:  No hay implementación de la Push API ni de la Notification API.
  IMPACTO:   Para un e-commerce, las push notifications son esperables para
             confirmación de pedidos, cambios de estado, ofertas, etc.
  UBICACIÓN: No existe en ninguna parte del proyecto.

─── 4.6 Sin Background Sync ───────────────────────────────────────────────────

  PROBLEMA:  No hay implementación de la Background Sync API.
  IMPACTO:   Operaciones offline (agregar al carrito, actualizar stock,
             cambiar estado de producto) fallan sin posibilidad de reintento
             automático cuando vuelva la conexión.
  UBICACIÓN: No existe en ninguna parte del proyecto.
  NOTA:      Las admin API routes POST ya devuelven 503 offline, pero no
             hay mecanismo para encolar y reintentar esas operaciones.

─── 4.7 Sin Install Prompt personalizado ──────────────────────────────────────

  PROBLEMA:  No se captura el evento beforeinstallprompt.
  IMPACTO:   No hay botón de "Instalar app" en la UI. El usuario depende
             del banner nativo del navegador.
  UBICACIÓN: No existe en ninguna parte del proyecto.

─── 4.8 Sin manejo de conectividad en la UI ───────────────────────────────────

  PROBLEMA:  No hay un indicador visual de estado de conexión en la interfaz.
  IMPACTO:   El usuario no sabe si está viendo datos cacheados o en tiempo
             real. El header X-From-Cache se setea en el SW pero ningún
             componente del frontend lo consume visualmente.
  UBICACIÓN: No existe como componente visual.
  NOTA:      El AdminHomePage sí tiene fallback a cache, pero no le indica
             al usuario que está viendo datos offline/cacheados.

─── 4.9 [NUEVO] PersistAdminRole no se limpia en layout.tsx raíz ─────────────

  PROBLEMA:  PersistAdminRole se incluye solo en admin/layout.tsx.
             PersistUserId limpia el userId cuando el status es
             "unauthenticated", pero PersistAdminRole solo setea "isAdmin"
             cuando es admin y lo remueve al desautenticar. Si un admin
             cierra sesión y otro usuario no-admin inicia sesión, el flag
             "isAdmin" podría quedar en localStorage si el nuevo usuario
             nunca visita una ruta /admin/ (donde está PersistAdminRole).
  IMPACTO:   Posible estado inconsistente de "isAdmin" en localStorage.
  UBICACIÓN: src/app/pwa/PersistAdminRole.tsx + src/app/admin/layout.tsx

─── 4.10 [NUEVO] AdminHomePage no incluido en el layout.tsx raíz ──────────────

  PROBLEMA:  El componente PersistAdminRole se importa en admin/layout.tsx
             pero NO en el layout.tsx raíz. Esto significa que la limpieza
             del flag "isAdmin" solo ocurre si el usuario navega a rutas
             de admin. Debería considerarse mover la persistencia al root
             layout para cobertura completa.
  UBICACIÓN: src/app/admin/layout.tsx (línea 4)

             y validan que token.role === "admin" antes de proceder. Los
             endpoints POST también tienen validación de body (productId,
             active/stock). Esto es un buen patrón de seguridad.

             por el usuario y no debe usarse para seguridad. Solo se usa
             para decisiones de UI/cache offline.
